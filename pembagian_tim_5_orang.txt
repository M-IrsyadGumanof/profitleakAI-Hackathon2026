 IRSYAD - BACKEND / API ENGINEER + TRAINING MODEL
 Branch milik: irsyad
 File milik : backend/main.py, backend/requirements.txt, train_v6.py
------------------------------------------------------------------------
Tujuan:
  Menyediakan API FastAPI yang melayani frontend, menjalankan model v6,
  serta bertanggung jawab atas proses training ulang model.

STATUS: SELESAI (lihat rincian di bawah untuk pemeliharaan)

Tugas yang sudah dikerjakan:
  1. Setup FastAPI + CORS untuk origin frontend
     (http://localhost:3000 & http://127.0.0.1:3000).
  2. Endpoint GET /api/health.
  3. Endpoint GET /api/model-info (metadata + scope cakupan model).
  4. Endpoint POST /api/predict (prediksi tarif ongkir wajar).
  5. Endpoint POST /api/detect-leak (2 detektor + reasons + risk_score).
  6. Endpoint POST /api/upload-csv (analisis batch dari file CSV).
  7. Model di-load SATU KALI saat startup lewat FastAPI lifespan
     (bukan per request), path dinamis berbasis lokasi file.
  8. Guard kompatibilitas fitur: backend menolak start jika jumlah fitur
     model tidak cocok (mencegah crash misterius).
  9. Validasi input terhadap valid_ranges -> HTTP 400 dengan
     {"detail": "<pesan ramah>"} (bukan 422).
 10. Training ulang model v6 lewat train_v6.py (lihat Bagian 5).
 11. requirements.txt sinkron dengan dependency yang dipakai.

Tugas lanjutan (pemeliharaan):
  a. Menjaga endpoint tetap sesuai KONTRAK (Bagian 4) saat frontend minta
     penyesuaian; koordinasi dengan Suhafdal.
  b. Membantu Febri saat QA menemukan masalah backend.
  c. Jika Galang menemukan kejanggalan model saat audit, tindak lanjuti
     di train_v6.py lalu latih ulang.

Deliverable:
  - API berjalan: /api/health, /api/model-info, /api/predict,
    /api/detect-leak, /api/upload-csv.
  - Skrip training train_v6.py yang reproducible.

Definition of Done: [TERPENUHI]
  - Semua endpoint merespons via HTTP nyata (sudah diuji dengan uvicorn,
    termasuk upload CSV multipart dan validasi 400).
  - Model di-load sekali (bukan per request).
  - Input di luar valid_ranges ditolak dengan 400 + pesan jelas.

 GALANG - ML / DATA ENGINEER (VERIFIKASI, NOTEBOOK & DATASET)
 Branch milik: galang
 File milik : model/ (pkl + info JSON), *.ipynb, fixtures/
------------------------------------------------------------------------
Tujuan:
  Menjadi verifikator independen atas model v6, memindahkan proses
  training ke notebook agar reproducible, dan menyediakan dataset uji
  (fixture) yang dipakai frontend, QA, dan demo.

CATATAN KEPEMILIKAN (penting, agar tidak salah paham):
  - Training v6 dikerjakan IRSYAD lewat train_v6.py.
  - Folder model/ secara FORMAL dimiliki Galang: Galang yang menjaga
    konsistensi artefak dan mendokumentasikannya.
  - Galang TIDAK perlu melatih ulang dari nol. Tugas Galang adalah
    memastikan model benar, terdokumentasi, dan punya data uji.

Tugas Ngoding (menyeluruh):
  1. AUDIT MODEL (verifikasi independen):
     - Load model/profitleak_final_model_v5.pkl, pastikan bisa dipakai.
     - Pastikan urutan fitur benar:
       ['weight_kg', 'distance_km', 'volume_cm3', 'price_log',
        'density_g_cm3'] dan price_log = log1p(price).
     - Reproduksi metrik: R2 uji = 0.7349 (v5 lama: 0.7227).
     - Cek threshold rasio = 3.09779 (bandingkan dengan file info JSON).
     - Cek margin_proba_threshold = 0.46 untuk detektor margin.
     - Laporkan jika ada angka yang tidak cocok dengan info JSON.
  2. NOTEBOOK:
     - Pindahkan alur train_v6.py ke Dataset_E_Commerce.ipynb agar bisa
       dijalankan ulang langkah demi langkah (dataset: archive.zip).
     - Beri penjelasan tiap sel: asal fitur, split 3 arah
       (latih/validasi/uji), cara threshold ditentukan.
  3. DATASET UJI / FIXTURE (paling dibutuhkan teman frontend):
     - Buat folder fixtures/ berisi CSV contoh, misalnya:
         fixtures/contoh_normal.csv      (transaksi sehat)
         fixtures/contoh_ongkir_mahal.csv(ongkir >> tarif wajar)
         fixtures/contoh_margin_tipis.csv(ongkir besar vs harga jual)
         fixtures/contoh_campuran.csv    (gabungan + 1 baris invalid)
     - Kolom wajib: weight_kg, distance_km, volume_cm3, price
       Kolom opsional: freight_value atau actual_rate, product_weight_g,
                       length_cm, height_cm, width_cm
     - Sertakan 1 baris sengaja invalid untuk menguji penanganan error.
  4. VISUALISASI & ANALISIS:
     - Distribusi rasio tarif, confusion matrix detektor margin.
     - Contoh kasus nyata yang terdeteksi (untuk materi demo).
  5. DOKUMENTASI METODE:
     - Jelaskan mengapa detektor `rate` lemah untuk kerugian jenis ini
       (median rasio hanya ~1.0x pada transaksi tidak ekonomis).
     - Jelaskan batas data: tidak ada kolom modal/diskon.
     - Jelaskan definisi ground truth: freight_value/price > 0.5.

Deliverable:
  - Laporan audit model (angka cocok/tidak cocok).
  - Notebook reproducible.
  - Folder fixtures/ berisi CSV siap pakai.
  - Catatan metode + grafik untuk demo.

Definition of Done:
  - Fixture bisa langsung dipakai Febri (QA) & Ihqfal (UI).

5. KONTRAK DATA / API  (TITIK TEMU - DIPELIHARA IRSYAD + GALANG)
========================================================================
Semua perubahan format WAJIB lewat kesepakatan ini dulu.
Base URL lokal: http://localhost:8000

------------------------------------------------------------------------
A. REQUEST - POST /api/predict dan POST /api/detect-leak
------------------------------------------------------------------------
Field WAJIB (4):
{
  "weight_kg":   0.05 .. 30.0,
  "distance_km": 1.4896 .. 3135.7885,
  "volume_cm3":  352.0 .. 244608.0,
  "price":       4.99 .. 2110.0
}

Field OPSIONAL (boleh tidak dikirim):
{
  "product_weight_g": <number>,   // gram; untuk hitung kepadatan
  "length_cm": <number>,
  "height_cm": <number>,
  "width_cm": <number>,
  "actual_rate": <number>         // KHUSUS /api/detect-leak
}
Catatan:
  - price_log & density_g_cm3 DIHITUNG BACKEND, jangan dikirim user.
  - Jika field opsional tidak dikirim, backend memakai nilai default.

------------------------------------------------------------------------
B. RESPONSE - POST /api/predict
------------------------------------------------------------------------
{
  "predicted_rate": 32.75,   // tarif ongkir wajar (BRL)
  "currency": "BRL"
}

------------------------------------------------------------------------
C. RESPONSE - POST /api/detect-leak
------------------------------------------------------------------------
{
  "predicted_rate": 32.75,
  "actual_rate": 900.0,          // dari actual_rate, atau price bila kosong
  "ratio": 27.4849,              // actual_rate / predicted_rate
  "is_leak": true,               // true bila salah satu detektor menyala
  "threshold": 3.09779,          // ambang RASIO tarif
  "currency": "BRL",
  "message": "<penjelasan singkat>",
  "risk_score": 0.87,            // 0..1 skor risiko gabungan
  "freight_ratio": 3.0,          // ongkir / harga jual
  "margin_risk_probability": 0.97, // probabilitas model risiko (0..1)
  "detectors": {
    "rate": true,                // tarif aktual > ambang rasio
    "margin": true               // model memprediksi transaksi tidak ekonomis
  },
  "reasons": [
    {
      "code": "rate_exceeds_fair" | "freight_eats_margin",
      "severity": "high" | "medium",
      "detail": "<penjelasan>",
      "remedy": "<saran tindakan>"
    }
  ]
}

------------------------------------------------------------------------
D. RESPONSE - POST /api/upload-csv  (multipart/form-data, field "file")
------------------------------------------------------------------------
Catatan: file .csv UTF-8; maksimal 50.000 baris dianalisis.
Kolom wajib: weight_kg, distance_km, volume_cm3, price
Kolom opsional: freight_value / actual_rate, product_weight_g,
                length_cm, height_cm, width_cm

{
  "filename": "contoh.csv",
  "currency": "BRL",
  "threshold": 3.09779,
  "margin_threshold": 0.46,
  "summary": {
    "total_rows": 4,
    "analysed": 4,
    "skipped": 1,
    "leaks": 2,
    "rate_leaks": 1,
    "margin_risks": 1,
    "estimated_loss": 875.95,
    "leak_rate": 50.0
  },
  "reason_breakdown": { "rate_exceeds_fair": 1, "freight_eats_margin": 1 },
  "recommendations": [
    { "code": "freight_eats_margin", "count": 1,
      "recommendation": "<saran tindakan>" }

6. RINGKASAN MODEL v6 (RUJUKAN CEPAT)
========================================================================
Artefak (nama dipertahankan agar tidak bentrok):
  - model/profitleak_final_model_v5.pkl
  - model/profitleak_final_model_info_v5.json

Isi model:
  - rate_model   : HistGradientBoostingRegressor (prediksi tarif wajar)
  - margin       : HistGradientBoostingClassifier (risiko tidak ekonomis)
  - Fitur tarif  : weight_kg, distance_km, volume_cm3, price_log,
                   density_g_cm3
  - Threshold rasio tarif : 3.09779
  - Threshold probabilitas margin : 0.46

Metrik (data uji, n = 16.754):
  - R2 uji                : 0.7349  (v5 lama 0.7227)
  - Detektor margin  P=0.889  R=0.831  F1=0.859
  - Detektor rate    P=0.667  R=0.006  F1=0.013  (lemah - lihat catatan)
  - Gabungan         P=0.887  R=0.836  F1=0.861
  - Rating model     : 75.6 / 100 (B)

Definisi ground truth:
  freight_value / price > 0.5  -> transaksi tidak ekonomis.

Catatan jujur:
  - Detektor `rate` lemah untuk kerugian jenis ini karena median rasio
    tarif pada transaksi tidak ekonomis hanya ~1.0x. Ini batas konsep,
    bukan bug. Detektor utama yang bekerja adalah `margin`.
  - Fitur turunan berbasis freight_value DITOLAK saat training karena
    menyebabkan target leakage (R2 melonjak palsu 0.73 -> 0.99).

        train_v6.py
