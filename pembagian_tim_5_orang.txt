------------------------------------------------------------------------
 IRSYAD - BACKEND / API ENGINEER
 Branch milik: feat/irsyad-backend
 File milik : backend/main.py, backend/requirements.txt
------------------------------------------------------------------------
Tujuan:
  Menyediakan API FastAPI yang melayani permintaan frontend dan menjalankan
  model untuk memprediksi tarif ongkir serta menandai kebocoran profit.

Tugas Ngoding (menyeluruh):
  1. Setup & pastikan server FastAPI + CORS berjalan (port 8000).
  2. Jaga endpoint GET /api/health tetap tersedia.
  3. Buat model request/response API (Pydantic) sesuai KONTRAK (Bagian 4).
  4. Buat endpoint POST /api/predict (prediksi tarif ongkir).
  5. Buat endpoint POST /api/detect-leak (prediksi + flag kebocoran/profit leak).
  6. Load model dari model/profitleak_final_model_v5.pkl (pakai joblib)
     satu kali saat startup (bukan tiap request).
  7. Implement validasi input terhadap valid_ranges dari JSON info:
     - weight_kg  : 0.05 - 30.0
     - distance_km: 1.4896 - 3135.7885
     - volume_cm3 : 352.0 - 244608.0
     - price      : 4.99 - 2110.0
  8. Implement logika deteksi memakai threshold = 1.102309 + drift protection.
  9. Tangani error dengan jelas (400 input tidak valid, 500 error server)
     dan kembalikan pesan yang bisa ditampilkan frontend.
 10. Menjaga requirements.txt sinkron dengan dependency yang dipakai.

Deliverable:
  - API berjalan; /api/health, /api/predict, /api/detect-leak siap dipakai.
  - Dokumentasi singkat kontrak endpoint (dibantu Febri).

Definition of Done:
  - Ketiga endpoint merespons via browser/curl dengan data uji nyata.
  - Input di luar valid_ranges ditolak dengan 400 + pesan jelas.
  - Model di-load sekali (tidak re-load per request).
  - Sudah di-merge ke develop & tidak menyentuh file di luar area milik.


------------------------------------------------------------------------
 GALANG - ML / DATA ENGINEER
 Branch milik: feat/galang-ml
 File milik : model/ (pkl + info JSON), notebook/
------------------------------------------------------------------------
Tujuan:
  Memastikan model final valid dan mendefinisikan cara pakainya (fitur,
  threshold, arti hasil) sehingga backend dan frontend memakai definisi
  yang sama.

Tugas Ngoding (menyeluruh):
  1. Verifikasi model final (.pkl) bisa di-load dan menghasilkan prediksi.
  2. Pastikan urutan fitur sesuai model (weight_kg, distance_km, volume_cm3,
     price_log) dan bahwa price_log dihitung dari price.
  3. Dokumentasikan cara menghitung prediksi & residual satu arah.
  4. Tetapkan aturan keputusan leak:
     - rasio = actual_rate / predicted_rate
     - leak jika rasio > threshold (1.102309) dengan normalisasi drift
       (baseline_median_residual = -0.011977).
  5. Sediakan fungsi bantu Python (notebook/modul model) untuk memprediksi
     & menilai leak, agar Irsyad memakainya sebagai rujukan.
  6. Siapkan data uji contoh (fixture) untuk QA (Febri) & demo.
  7. Catat metrik (R2 test 0.7227, detection rate, FPR 0.17) untuk docs.

Deliverable:
  - Notebook/modul berisi fungsi prediksi + deteksi leak yang terbukti jalan.
  - Contoh input/output (fixture) untuk pengujian.
  - Catatan definisi fitur, threshold, dan interpretasi hasil.

Definition of Done:
  - Fungsi prediksi & deteksi menghasilkan output benar untuk data contoh.
  - Definisi & rumus tersedia sebagai rujukan Irsyad, Ihqfal, Suhafdal, Febri.
  - Sudah di-merge ke develop & tidak menyentuh file di luar area milik.

4. KONTRAK DATA / API (TITIK TEMU - DITULIS IRSYAD + GALANG)
========================================================================
Semua perubahan format WAJIB lewat kesepakatan ini dulu.

Request (POST /api/predict dan POST /api/detect-leak):
{
  "weight_kg":   0.05..30.0,
  "distance_km": 1.4896..3135.7885,
  "volume_cm3":  352.0..244608.0,
  "price":       4.99..2110.0
}

Response /api/predict:
{
  "predicted_rate": <number>,   // tarif ongkir prediksi (mata uang BRL)
  "currency": "BRL"
}

Response /api/detect-leak:
{
  "predicted_rate": <number>,
  "actual_rate":    <number>,      // = price masukan
  "ratio":          <number>,      // actual / predicted
  "is_leak":        <boolean>,     // ratio > threshold
  "threshold":      1.102309,
  "currency":       "BRL",
  "message":        "<string penjelas>"
}

Error (400 / 500):
{
  "detail": "<pesan error yang bisa ditampilkan ke pengguna>"
}

Catatan: field price_log dihitung di backend (log dari price), tidak dikirim user.

5. FASE PROJECT (URUTAN, TANPA JADWAL JAM)
========================================================================
Ringkasan urutan pemicu:
  Fase 1 (Irsyad + Galang) -> Fase 2 (semua paralel) -> Fase 3 (Suhafdal)
  -> Fase 4 (Febri) -> Fase 5 (semua / merge ke main)

  Yang MEMULAI project lebih dulu = IRSYAD + GALANG (menyusun kontrak).

------------------------------------------------------------------------
Fase 1 - INISIASI & KONTRAK        (branch: develop)
  MULAI DARI  : Irsyad + Galang (paling awal).
  AKTOR       : Irsyad + Galang menulis KONTRAK DATA/API (Bagian 4).
  SYARAT MASUK: kebijakan tim sudah disepakati.
  OUTPUT      : Kontrak disetujui semua anggota.
  PEMICU FASE 2: kontrak selesai & disetujui -> semua boleh mulai Fase 2.

------------------------------------------------------------------------
Fase 2 - PENGEMBANGAN PARALEL       (branch: masing-masing feat/*)
  MULAI SETELAH: Fase 1 (kontrak) selesai.
  AKTOR (jalan BERSAMAAN, tidak saling menunggu):
    Galang   : finalisasi fungsi prediksi + deteksi + fixture.
    Irsyad   : bangun endpoint backend sesuai kontrak.
    Ihqfal   : bangun UI dashboard (pakai mock/data contoh).

    Febri    : bangun komponen reusable + skrip uji + README awal.
  -> Tiap orang bekerja di branch pribadinya, tidak saling menimpa.
  OUTPUT      : tiap bagian berjalan sendiri-sendiri di branch masing-masing.
  PEMICU FASE 3: backend (Irsyad) & UI (Ihqfal) sudah bisa dipakai.

------------------------------------------------------------------------
Fase 3 - INTEGRASI                 (feat/* -> develop)
  MULAI SETELAH: Fase 2 -> backend + UI + modul api siap.
  AKTOR UTAMA : Suhafdal (penggerak integrasi).
    - Suhafdal menyambungkan UI (Ihqfal) ke backend (Irsyad).
    - Ihqfal memasang komponen dari Febri.

Fase 4 - QA MENYELURUH              (branch: develop)
